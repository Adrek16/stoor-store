# ستور — متجر عطور وإكسسوارات وحقائب

متجر إلكتروني عربي (RTL) للعطور والإكسسوارات والحقائب — للرجال والنساء والأطفال، مبني على **Next.js 16 + TypeScript + Tailwind CSS v4**، ومخصّص للسوق **اليمني** (ريال يمني، استلام من المتجر، لا شحن ولا كوبونات).

مستوحى في بنيته وأسلوبه من `joj-accessories.com` — لكن بمعمارية مخصّصة وأسرع، وبتصنيف يغطي **الرجال والنساء والأطفال**، و**العطور والإكسسوارات والحقائب**.

> **الخطة الحاكمة لشاشات العملاء:** [`docs/customer-screens-plan.md`](docs/customer-screens-plan.md)  
> **خطة لوحة المدير:** `C:\Users\L\Desktop\مدير\docs\manager-screens-plan.md`

## التشغيل

```bash
npm install
npm run dev      # http://localhost:3000
npm run build    # نسخة الإنتاج
npm start        # تشغيل نسخة الإنتاج

# قاعدة البيانات
npm run db:check    # فحص الاتصال والجداول
npm run db:migrate  # تنفيذ supabase/schema.sql
npm run db:seed     # إدراج التصنيفات/المنتجات الناقصة فقط (آمن للتكرار)
npm run db:seed:force # استبدال الصفوف الموجودة ببيانات المشروع الأصلية
```

> إن كان `npm install` بطيئاً، استخدم مرآة أسرع:
> `npm install --registry=https://registry.npmmirror.com`

## ما هو جاهز

- ✅ صفحة رئيسية كاملة: شريط متحرك، هيرو، تصنيفات، أقسام منتجات، آراء عملاء، نشرة بريدية
- ✅ صفحات تصنيفات مع ترتيب (سعر / تقييم)
- ✅ صفحة منتج: معرض، اختيار حجم/لون، هرم نوتات عطرية، أكورديونات
- ✅ سلة تعمل بالكامل (Context) مع درج جانبي — **لا تحجز مخزوناً**. *قيد التطوير:* ربطها بحساب العميل المسجّل وحفظها على الخادم (انظر خطة العملاء).
- ✅ **إتمام الطلب**: نموذج مستلم بتحقق (اسم + جوال يمني فقط، بلا عنوان/مدينة)، دفع عند الاستلام أو تحويل بنكي أو محفظة محلية، ملخّص حيّ. *قيد التطوير:* يتطلب تسجيل دخول وربط الطلب بـ`customer_id`.
- ✅ **صفحة تأكيد الطلب** `/order/[id]` برقم طلب وتاريخ وفاتورة وروابط متابعة
- ✅ **`POST /api/orders`** — الطلبات تُحفظ في قاعدة البيانات، والأسعار تُعاد حسابها هناك. **المخزون يُخصم عند تأكيد المدير، لا عند الإرسال**
- ✅ **إدارة المتجر في تطبيق محلي منفصل** («مدير» على `127.0.0.1:4100`) — الطلبات والمنتجات والتصنيفات والإعدادات **وشاشة «معلومات المتجر» (الشعار + كل النصوص الظاهرة)**. لوحة `/admin` القديمة أُزيلت من المتجر نهائياً.
- ✅ **تحويل دائم لروابط التصنيفات والمنتجات القديمة** — تغيير قسم تصنيف أو تصنيف منتج من لوحة المدير يحوّل الرابط القديم (308) بدل 404، عبر `src/proxy.ts` وسجلّي `category_slug_history` و`product_slug_history`.
- ✅ **المنتجات من Supabase** — تُقرأ من قاعدة البيانات، ومع سقوط آمن للبيانات المحلية إن انقطع الاتصال
- ✅ **خصم مخزون ذرّي** — دالة `confirm_order_stock` في Postgres (تُستدعى عند تأكيد المدير، لا عند الإرسال)
- ✅ **صور المنتجات الحقيقية** — تُرفع إلى Supabase Storage وتُعرض عبر `<img>` في البطاقة والمعرض (مع `ProductArtwork` كبديل)
- ✅ **معلومات المتجر ديناميكية** — الهيدر/الفوتر/الشعار/الإعلانات/الهيرو/التواصل كلها من `settings.store_info` (يحرّرها المدير)
- ✅ بحث، 404 مخصّص، 12 صفحة سياسات ومعلومات
- ✅ SEO: metadata، JSON-LD (Store + Product)، `sitemap.xml`، `robots.txt`، أيقونة متجر
- ✅ RTL كامل + خط عربي محلي (بدون طلبات خارجية)
- 🗑️ **الكوبونات والدفع بالبطاقة والشحن/التوصيل والتغليف أُزيلت** — الدفع يدوي (عند الاستلام + تحويل/محفظة)، والاستلام من المتجر.


## المتغيرات البيئية

انسخ `.env.example` إلى `.env.local`:

| المتغير | الوظيفة |
|---|---|
| `SESSION_SECRET` | مفتاح توقيع كوكيز المتجر (جلسة العميل + الوصول للطلب) — **مطلوب**، ولّده بطول 32 بايت |
| `SUPABASE_URL` | عنوان مشروع Supabase |
| `SUPABASE_SERVICE_ROLE_KEY` | مفتاح الخادم (لا anon) — سري |
| `SUPABASE_ANON_KEY` | مفتاح منشور لتسجيل/دخول العملاء (Supabase Auth) — آمن للنشر |
| `SUPABASE_ACCESS_TOKEN` | اختياري — لتنفيذ المخطط عبر `db:migrate` |
| `DATABASE_URL` | اختياري — بديل لتنفيذ المخطط عبر Postgres |
| `STORE_REVALIDATE_SECRET` | سر مشترك يفعّل `POST /api/revalidate` لتحديث كاش الكتالوج فوراً بعد تعديل Supabase مباشرة |

بدون متغيرات Supabase، يعمل المتجر على `lib/products.ts` وتُخزَّن الطلبات في `.data/orders.jsonl` (تطوير فقط).

### الدفع — يدوي بلا بوابة

الطرق (لا كوبونات ولا بطاقة):

- **الدفع عند الاستلام** — عند استلام الطلب من المتجر.
- **تحويل بنكي** — بيانات الحساب من لوحة المدير + رفع صورة الإيصال (`POST /api/orders/[id]/proof`) ومراجعتها في اللوحة.
- **محافظ محلية** (جوالي، جيب، حاسب، فلوسك، ون كاش، وغيرها) — يديرها المدير من قسم «الدفع والمحافظ»، وبنفس آلية الإيصال.

> `src/lib/payments/*` (طبقة Moyasar القديمة) **يُحذف** — لا بوابة دفع في المشروع.

## ملاحظات

- **الأسعار بالريال اليمني (ر.ي)**. المنتجات القديمة بالريال السعودي تُحذف وتُعاد الأسعار من لوحة المدير.
- الصور: تُرفع إلى Supabase Storage (`store-assets` للشعار، وbucket المنتجات للصور) وتُعرض عبر `<img>`؛ `ProductArtwork` (SVG مولّد) بديل عند غياب الصورة.
- رقم الواتساب والعنوان (صنعاء) وكل نصوص المتجر تُضبط من شاشة «معلومات المتجر» في لوحة المدير — لا تُحرَّر في `lib/site.ts` مباشرة.
- **لا شحن، لا تغليف، لا كوبونات.** الاستلام من المتجر، وتأكيد الطلب يتم عبر واتساب/هاتف مع المدير.
